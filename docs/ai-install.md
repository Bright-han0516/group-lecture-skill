# 给 AI 的安装与验收流程

这是 [中文快速指南](../README.zh-CN.md) 中短提示词引用的完整流程。目标是让同事用自己电脑上的 AI 助手安装 `group-lecture-builder`，并验证它能不能在其他项目使用。**这次只安装和测试，不开始制作讲义。**

## 1. 先检查环境和安装方式

- 阅读 [README.zh-CN.md](../README.zh-CN.md)、[SKILL.md](../SKILL.md)、[安装说明](installation.md) 和 [install.sh](../install.sh)。运行脚本前先阅读实际内容，确认操作和写入位置符合用户授权。
- 确认操作系统、当前 AI 客户端、终端与本地读写权限，以及目标是不是用户自己的电脑。云端能编译，不等于已装到用户电脑。仅能聊天或浏览时，说明限制，建议切换到有本地终端和文件权限的客户端；若只需审阅内容，可使用 [PROMPT.md](../PROMPT.md) 的审阅模式。
- 仓库安装器支持 Codex、Claude Code；Windows 优先检查 WSL，原生 PowerShell 并非本仓库已验证的路径。其他客户端先核实其用户级 Skill 发现机制，不要照搬目录；没有验证则如实报告。

## 2. 安装成用户级 Skill

- 按 [安装说明](installation.md) 把公开仓库放在稳定的用户目录，例如 `$HOME/.local/share/group-lecture-builder`。用当前工具对应的 `bash install.sh --hosts codex` 或 `bash install.sh --hosts claude`。不要默认安装到其他客户端或其他项目。
- 先检查是否已有源码目录、工作区修改、同名 Skill 或链接。确认是同一仓库、没有未保存改动且可仅快进时，才按更新流程操作；需要覆盖现有文件、替换链接、删除目录或处理分叉时先停下说明并征得同意。不要强制更新、重复安装或修改无关项目。
- 验证用户级入口存在，链接指向正确仓库且 `SKILL.md` 可读。记录安装位置。该检查本身不能证明客户端已经发现 Skill，也不能证明能构建 PDF。

## 3. 检查依赖并运行 Demo

- 检查 Git、Python 与实际执行的 Python 是否可导入 PyMuPDF（`fitz`）、XeLaTeX、所需 TeX Live 宏包和字体。优先使用仓库自带的字体及现有兼容环境。若需要安装系统软件、管理员权限、大型下载、覆盖文件或改系统配置，先取得同意。不需要提权且明确在授权范围内的修复尽可能直接完成，如在新的隔离环境内配置 Python 依赖。
- 在仓库根目录执行 `./bootstrap.sh`。确认预检通过、新生成学生版和答案版两份 PDF、结构 QA 和 Demo 特性检查均通过。检查构建日志与 QA 中的编译、缺图、字体问题；以退出状态、`READY` 和实际产物为凭据，不把旧产物当作本次生成。
- 如失败，查看脚本的 `FAIL` 或 `fix:` 信息，修复授权范围内的问题并重试。若无法修复，把失败项、原因和最小下一步写清楚，不跳过检查。

## 4. 独立验证跨项目发现

在仓库之外的临时项目目录开启当前客户端的新会话，不提供 Skill 路径，也不把仓库的 `AGENTS.md` 复制进去。只说：

> 请找到并调用 group-lecture-builder，说明它的用途和首次运行要做什么。只验证 Skill 已加载，不制作讲义。

用客户端的 Skill 列表、实际加载记录或等效证据确认它从用户级入口发现并读取了 Skill。文件存在、AI 复述 Skill 名称、从仓库内读到文档，均不能单独证明跨项目发现。若无法自动开新会话或无法观察加载结果，请标为「尚未验证」，并把上面一句留给同事在新会话中测试。

## 5. 用中文汇报并停下

分别说明：**用户级安装**、**PDF 构建环境**、**Demo 双 PDF 与结构 QA**、**跨项目发现**。每项给出已通过、失败或尚未验证，以及一条必要证据或下一步。Demo 只验证环境与示例，不代表真实课程内容已通过学科审核。

最后给出自然语言调用示例即可，不要执行：「请调用 group-lecture-builder，根据我提供的考纲和获准使用的真题制作一份〔学科／考局／主题〕讲义。先核对资料，再规划学生版和答案版。」试用其他学科时按实际考纲、题型和评分方式调整，不机械套用物理规范。
